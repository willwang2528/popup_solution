> 正式数据锚：真实同步 Android screenshot + accessibility representation。PopSweeper/RICO 仅是协议与来源适配 pilot。

## Block 1 — Capture feasibility gate

目标：证明正式输入不是 RICO 语义树的替代品，而是真实同步 Android accessibility observation。

1. 在至少 5 个受控／获授权 App 或 source groups 中捕获稳定动作前状态。
2. 每个 item 保存 screenshot hash、raw accessibility dump、采集时间、状态 fingerprint、设备／OS／App／locale／collector version 和失败原因。
3. 采集 popup、visually similar no-popup 和边界例；所有记录无点击、无关闭、无 post-action observation。
4. 先完成小型 feasibility set；只有树图同步、provenance、license/privacy 和 group identity 均可审计才扩展。

硬停止：没有真实同步 Android accessibility capture，或不能形成至少 5 个 group、3 个 popup template families，则停止 benchmark 主实验；不得用 PopSweeper/RICO 补位。

## Block 2 — G1/G2 gold 与规模冻结

### G1：截图事实 gold

- 两名真人只看截图，独立标注 `popup|no_popup|uncertain|unusable|out_of_scope`、visible message、critical facts 与 observability。
- `out_of_scope` 必须填写预定义原因，不进入主指标；`uncertain` 不能承担范围排除。
- 第三名真人重查全部 item 后裁决；presence observed agreement、Cohen κ、message/slot agreement 与 ambiguity cap 按冻结阈值执行。

### G2：结构充分性 audit

- 另一组真人在 G1 冻结后检查 raw structure + frozen G1 gold，标完整、缺失、污染、错序、过期和矛盾。
- 两人独立、第三人仲裁；普通分歧仍无法解决则 `cannot_resolve`。
- 若发现 G1 实质错误，G2 不改写 G1：item fail closed，退回版本化 G1 修正，更新 hash 后重启 G2。

### 正式规模

30-item 只用于协议 pilot。正式 N 在 pilot 后根据以下量冻结：真实 gap prevalence、App/template cluster size、paired VPMA 方差、目标 CI 宽度和可用 group 数；不预填任意 N。方法贡献还要求至少 20 个 non-synthetic gap positives，且不能由单一 group 贡献。

硬停止：G1 presence κ < 0.70 且两次预先编号的协议修订仍失败；或 G2 agreement < 0.70。后者允许保留 message dataset，但不能把 gap 当 gold。

## Block 3 — Strong family comparison

只比较三族、全部 no-action：

1. **Structure-only**：raw hierarchy flatten／规则与同一冻结语言 backbone。
2. **Vision-only**：OCR-only、screenshot-only frozen VLM。
3. **Fusion/allocation**：always-on、empty-tree gate、random-K、message-sufficiency gate（MG-PU）。

PopSweeper exact 若缺代码、权重、阈值、temporal frames 与 detector assets，保持 NO-GO；论文约束 reconstruction 或增加 popup ROI 的 adaptation 必须改名，不能冒充 exact baseline。

共享冻结项：

- 相同 observation、split、test item 和 gold；
- 同一可用 backbone、system instruction、输出 schema、temperature、max tokens、retry/timeout 和 parser；
- 图像解码、resize、color space、OCR engine/version、ROI 来源、结构序列化、节点排序、文本 normalization、截断和去重规则；
- 方法 prediction 在 gold 解锁前持久化并绑定实现／配置／输入 hash。

主指标：VPMA + coverage。并列报告 Presence Macro-F1、message semantic correctness、critical-fact precision/recall、critical hallucination rate、selective risk、visual-call rate、decoded pixels、tokens、p50/p95 latency 和成本。字符串 exact/token-F1 仅辅助。

## Block 4 — Matched-budget allocation isolation

预注册至少三个 operating points，而不是只比一个调用率。这里的 K 是冻结评测 item 集上的视觉调用预算比例，不是调用次数分位数：

- `K25`：最多 `ceil(0.25 × N)` 个 item 调视觉；
- `K50`：最多 `ceil(0.50 × N)` 个 item 调视觉；
- `K100`：`N` 个 item，always-on 自然上界。

若 API／像素成本使 K 比例不能代表实际预算，再同时报告等 decoded-pixel 与等货币成本点，但不得事后选择唯一有利口径。条件视觉方法在同一 K 下比较 message-sufficiency、empty-tree 和 seeded random-K；always-on 同时报自然预算与 quality–coverage–cost Pareto。

主确认比较与 power/precision 规划固定为：`MG-PU message-sufficiency gate vs seeded random-K at K50`。它直接隔离“是否把同样的视觉预算分配给正确 item”。样本量规划使用 pilot 的 paired VPMA difference 与 App/template cluster 方差；结构／视觉／always-on 家族比较为关键次级分析。

统计：在冻结 test 上做 paired difference，以 App/template group cluster bootstrap 95% CI。主确认端点只有上述 K50 comparison，不做多重比较校正；预先命名的次级方法比较使用 Holm correction；gap tier、popup type、message complexity 等探索性分层使用 Benjamini–Hochberg FDR（`q=0.10`）并明确标为 exploratory。若 group 数不足以支持 cluster inference，只报告 exploratory CI 与逐 group 结果，不写显著性主张。

方法 superiority 继续门：主确认 K50 比较通过，且相对 dev 上冻结的 strongest deployable matched-budget baseline 的 VPMA 差异至少 +2 percentage points、校正后 CI 不跨 0，并且 coverage、critical hallucination 和实际预算没有恶化。任一条件达不到即撤销 superiority；+5pp 仅作为强效果解释，不作为改结果的后验阈值。

## Block 5 — Failure、叙事出口与发布

预注册分层：gap tier、popup type、App/template、message complexity、structure availability、语言和 out-of-scope disposition。四种结果出口：

| 观察 | 合法结论 |
|---|---|
| gate 同预算胜出 | PMAB measurement + conditional allocation 的经验收益 |
| null | PMAB + 本数据范围内 gate 无额外收益 |
| vision-only 胜 | 当前结构不足，vision-first 更强 |
| structure-only 近 ceiling 或真实 gap <10% | structure sufficiency measurement；停止高影响方法贡献 |

公开闸：逐 item privacy/PII、EXIF、redistribution/license、redaction 和 source attribution 全通过；受限媒体只发布 ID/hash/annotation/downloader 或 adapter，不重新分发。clean clone 必须重跑 schema、协议、baseline 和表格生成。

当前 30-item pilot 的技术媒体 QA 已通过，但真人 gold=0、经验评分=0；因此研究文档和代码可公开，经验数据继续 NO-GO。
